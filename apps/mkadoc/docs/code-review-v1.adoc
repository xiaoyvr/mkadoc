= Code review: v1 architecture

This page records the findings of a code review of the v1 multi-format
architecture. It is a living list — items are checked off as they are fixed.

== P1 — must fix

- [x] *Extension-registry plumbing in `src/plugin/host.js` is dead and leaks
  AsciiDoc into core.* `registerExtension`, `registerExtensionRegistry`,
  `state.extensionRegistry`, `state.pendingExtensions`, and the `registry`
  getters are unused in production (`mkadoc:asciidoc` keeps its registry in a
  closure; kroki moved to the `diagram` service). Removed.

== P2 — design smells

- [x] *`addAttributes` / `attributes` is a leaky, AsciiDoc-shaped abstraction
  in core.* Only the AsciiDoc renderer interprets it; Markdown ignores it.
  `mkadoc:nav` set `icons: font` (an AsciiDoc attribute) globally. Fixed: the
  `addAttributes` / `attributes` channel is removed entirely — `icons: font`
  is now the AsciiDoc renderer's own conversion default (the bundled theme
  ships the Font Awesome glyph rules it pairs with).
- [x] *Module-level `hostRef` singleton in `src/builtins/asciidoc.js`.* Set in
  the factory, read by `render()` and the module-level
  `ServiceSyntaxHighlighter`. Fixed: the highlighter is now registered
  per-instance with a closure over `host`
  (`registerServiceSyntaxHighlighter`), and all `hostRef` reads in
  `render`/`renderFragment`/`applyDiagramService` use the factory's `host`
  parameter directly.
- [x] *No plugin teardown/dispose lifecycle.* Removing `afterPluginsLoaded`
  also removed the only teardown path; shiki's highlighter lingers when removed
  from config. Added an optional `dispose(host)` hook (called on `plugins`
  config change under serve) and wired shiki to release its highlighter. Also
  added a loading-phase gate on `getService` + a `requires` service contract —
  see `src/plugin/host.js` / `src/plugin/load.js`.
- [x] *Renderer precedence is implicit and order-dependent.* `findPageFile`
  (in `mkadoc:nav`) returns the first renderer whose extension matches; order is
  "config order, then `mkadoc:asciidoc`, then `mkadoc:markdown`". Won't do —
  decided by design: the first-registered renderer wins and dispatch is
  deterministic; no renderer shares an extension today, so no material impact
  on end users.
- [x] *`sourceForPathname` is unused in production* — removed with the nav model.
- [x] *`listSourcePages` has an AsciiDoc fallback regex* (`/\.(?:adoc|asciidoc)$/`)
  used only when `rendererForPath` is omitted; every caller (build, decide-mode,
  sitemap) passes it. Fixed: `rendererForPath` is now required and the AsciiDoc
  regex is gone — omission fails loudly instead of silently degrading to
  AsciiDoc-only page discovery.

== P3 — minor / dead code

- [x] *`extractBody` / `extractHeadMeta` use `indexOf('<body')` + a `<meta>`
  regex* over the full standalone HTML. Fixed: both now parse with
  `node-html-parser` (promoted to a runtime dep) — body extraction via
  `body.innerHTML`, head metas via structured attribute checks (the previous
  `!== null` check was in fact buggy for absent attrs, dropping all renderer
  metas).
- [x] *`assemblePage` emits plugin-supplied attribute names unsanitized* (values
  are escaped, names are not). Won't do — accepted: plugins are trusted code
  and only plugins supply head links/scripts; defense-in-depth not worth the
  code.
- [x] *`copyAssets` trusts renderer-returned relative paths*; core does not
  re-validate before `path.join(cfg.root, rel)`. Fixed: paths are resolved and
  rejected when they escape the project root (warn + skip), defense-in-depth
  behind the renderer-side `collectAssets` guard.
- [x] *Markdown `extractMeta` title fallback reads only ATX headings* (`# T`),
  not setext (`T\n===`). Fixed: `firstHeading` also matches setext h1
  (`=`) underlines (used for both `extractMeta` and the page `<title>`); a
  setext h2 (`---`) is still not a document title.
- [x] *Markdown `renderFragment` ignores `attributes` and `baseDir`* — fine for
  nav today, but inconsistent with the contract and the AsciiDoc renderer.
  Fixed: the AsciiDoc-shaped `RenderInput.attributes` bag is gone entirely —
  replaced by an explicit format-neutral `linkPrefix` field (nav's real need;
  the asciidoc renderer maps it to `relfileprefix` internally). Markdown's
  fragment path now accepts the full contract shape (`baseDir`/`linkPrefix`),
  with its no-op documented.
- [x] *Topbar scroll-swap only works for AsciiDoc pages.* `TOPBAR_JS` read
  `#header h1` for the document title; Markdown pages emit a bare `<h1>` with
  no `#header`, so the brand never swapped on scroll for Markdown. Fixed: the
  page wrapper now emits the renderer-declared title as
  `<body data-doc-title="…">` and `TOPBAR_JS` reads that — the swap timing is
  a pure scroll threshold, so chrome never parses renderer body markup (h1,
  h2, or no heading, any renderer).
- [x] *`extractFirstLink` (asciidoc) regexes over rendered inline HTML.*
  `doc.findBy(...)` + `getText()` yields `<a href="...">label</a>`, which nav
  parsed with a regex. Fixed: the block text is parsed with `node-html-parser`
  and the first `<a>` read structurally — href + text (entities decoded),
  replacing `stripInlineTags`. Same parser family as `extractBody`/
  `extractHeadMeta`.
- [ ] *Auto-nav + site map resolve every page's title via `extractMeta` each
  build.* The auto-nav tree is cached per source within a build, but the site
  map is not; both read every page's metadata. Fine for small sites; worth a
  cache/`writeIfChanged` pass for large ones.
- [x] *Nav label-staleness state is module-level, in-memory* (`navReferenced` /
  `labelCache` / `autoNavCache`). Won't do — accepted and unchanged: the
  staleness memory only needs to survive rebuilds inside one `serve` process;
  the CLI `build` is always `forceFull`, so a fresh process has no stale-label
  risk.

== Docs drift

  removal. (Removed in P1.)
- [x] The `diagram` service's `attributes` adapter being AsciiDoc-specific is
  not called out. (Added the note in plugins.adoc.)
