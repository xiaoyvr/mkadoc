= mkadoc

Write documentation in AsciiDoc, Markdown, or any supported markup and get a
static site you can preview locally and publish cleanly.

mkadoc is for people who want:

* docs that stay in their source markup (AsciiDoc, Markdown, …)
* a fast edit loop (`serve` with live reload; incremental rebuilds when possible)
* optional extras — sidebar nav, syntax highlighting, diagrams — that work across formats
* monorepo-friendly sources (`docs/`, `apps/*/docs`, …) in one site

== Approach

mkadoc treats your project as:

* **Sources** — one or more documentation trees listed in `sources`; each source is a tab. `index.<ext>` is the entry point of each source.
* **Pages** — a *renderer* converts each page file to HTML. Renderers are plugins: `mkadoc:asciidoc` (`.adoc`, `.asciidoc`) and `mkadoc:markdown` (`.md`, `.markdown`) are built in and auto-loaded.
* **Output** — HTML under `output` (default `site/`)
* **Plugins** — feature plugins (`mkadoc:topbar`, `mkadoc:nav`, `mkadoc:shiki`, …) decorate pages through a service registry, regardless of the page's markup.

Configuration is plain YAML in `mkadoc.yaml` (see xref:architecture-v1.adoc[Architecture v1] for the rationale).

Some conventions:

* **Config file**: `mkadoc.yaml` under repository root
* **Site root**: `serve` redirects `/` to the *first* source's index page
* **Source-bar label**: `:nav_label:` / frontmatter `nav_label`, else doctitle/title, else last mount segment, else `Docs`
* **Pages**: files owned by a renderer; names starting with `_` are ignored
* **Cache**: `.mkadoc/` under repository root (not configurable — add it to `.gitignore`). Includes the include-dependency graph (`.mkadoc/deps.json`) used for incremental rebuilds when an included partial changes.
* **Output**: HTML under `site/` by default, configurable with `output:`
* **Includes/partials**: editing an included partial rebuilds only the pages that depend on it. Site-wide chrome inputs (`index.*`, logo overrides, `_nav.adoc`/`_nav.yaml`) rebuild every page incrementally. `_theme/*.css` only rewrites stylesheets (assets). An unused partial with no known dependents is a no-op. Config changes still force a full rebuild.

== Get started

From a project with `mkadoc.yaml` and source trees:

[cols="1,3"]
|===
| Command | What it does

| `build` | Full rebuild of all sources.
| `serve` | Full build, watch, serve `output/` with live reload.
| `publish` | Delete `output` + `.mkadoc/`, then full rebuild (for deployment).
| `check` | Verify source dirs and run enabled plugin health checks.
|===

=== Config shape

----
sources:
  - docs
  - apps/mkadoc/docs
output: site
plugins: {}
serve:
  remote: false
  port: 8000
----

Built-in renderers (`mkadoc:asciidoc`, `mkadoc:markdown`) are enabled by
default. List a renderer under `plugins:` only to pass it options (e.g.
`mkadoc:markdown: { html: true }`).

== Customization (`_theme/`)

Customization is plain CSS under the first source's `_theme/` directory:

* `_theme/theme.css` — global overrides appended after the default theme.
* `_theme/topbar.css` — overrides appended after the topbar defaults.
* `_theme/nav.css` — overrides appended after the sidebar/nav defaults.

`_assets/` still holds raw static files (logo override, favicon) and is copied
to the output as before.

== Assets

Referenced local files are copied into the output automatically — no config.
During a page build, the renderer reports referenced local files (AsciiDoc
images/links/video, Markdown images/links) and mkadoc copies each to the
mirrored path under `output/`, skipping unchanged files.

Convention: the **first source's `_assets` folder is always copied** to
`<output>/<first source path>/_assets` (e.g. `docs/_assets/` → `site/docs/_assets/`).
Put chrome-level files there (favicon, …); no page reference is needed.
The `_` prefix keeps the folder out of page discovery.

**Site logo (convention, no config):** `mkadoc:topbar` emits a clickable logo in the
topbar linking to the first source's home (`…/index.html`).

* Default: package icon at `/styles/default-logo.svg`
* Override: if the first source has `_assets/logo.svg` or `_assets/logo.png`
  (SVG preferred when both exist), that file is used instead

== Plugins

Enable feature plugins under `plugins:`. Renderers are auto-loaded; feature
plugins are renderer-agnostic and share capabilities through a service
registry (e.g. `mkadoc:shiki` provides `syntax-highlight`, consumed by every
renderer).

[cols="1,3"]
|===
| Locator | Role

| `mkadoc:topbar` | Sticky topbar: site logo + brand from `sources` (first in config order).
| `mkadoc:nav` | Site navigation: level-1 **source bar** under the topbar (one link per source) + level-2 **article sidebar** (per-source lists from each `_nav.adoc` or `_nav.yaml`).
| `mkadoc:shiki` | Build-time syntax highlighting for code blocks (all renderers).
| `mkadoc:asciidoc` | Built-in renderer for `.adoc` / `.asciidoc` (auto-loaded).
| `mkadoc:markdown` | Built-in renderer for `.md` / `.markdown` (auto-loaded).
| `file:./apps/mkadoc-plugin-kroki` | Diagram blocks via Kroki (`server_url` required) — external plugin in this repo.
|===

Common options (defaults shown):

* `mkadoc:nav` — enable with `{}` (no options)
* `mkadoc:shiki` — `theme: github-light-default`
* `mkadoc:markdown` — `html: false` (allow raw HTML)
* `file:./apps/mkadoc-plugin-kroki` — `server_url: …` (required; reference external plugin in this repo)
