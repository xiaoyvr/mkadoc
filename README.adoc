= mkadoc monorepo

Build and serve documentation (AsciiDoc, Markdown, …) as a static site.

This repository is a monorepo with three packages under `apps/`:

* `apps/mkadoc` — the `mkadoc` CLI (build, serve, check) and its builtin
  plugins (`mkadoc:topbar`, `mkadoc:nav`, `mkadoc:shiki`). Contains its own
  Nix flake (`apps/mkadoc/flake.nix`) that packages the CLI and its tests.
* `apps/mkadoc-plugin-host` — the `@mkadoc/plugin-host` package: the plugin
  contract and test host. A devDependency of `apps/mkadoc` and of
  `apps/mkadoc-plugin-kroki`.
* `apps/mkadoc-plugin-kroki` — the reference *external* plugin: renders
  `[diagram]` blocks through a Kroki server (`server_url` required).

== Develop

Each package is a standalone npm package with its own `package-lock.json`:

[source,console]
----
cd apps/mkadoc
npm install
npm test
npm run check
----

`file:../mkadoc-plugin-host` devDependencies resolve to the sibling package
in this monorepo, so install from the package directory (or use npm
workspaces at the root if you prefer a single lockfile).

== Site

The repo is itself a mkadoc site: the root `mkadoc.yaml` configures a build of
the three package doc trees (`apps/mkadoc/docs`, `apps/mkadoc-plugin-host/docs`,
`apps/mkadoc-plugin-kroki/docs`) into `site/`. Built-in renderers
(`mkadoc:asciidoc`, `mkadoc:markdown`) are auto-loaded. The `mkadoc` command
runs from source via npm (`npm link` in `apps/mkadoc`, or
`node apps/mkadoc/bin/mkadoc.js`); `npm install` in `apps/mkadoc` is required
first:

[source,console]
----
mkadoc check   # validate config + plugins (reports Kroki reachability)
mkadoc build   # render site/ (no server needed; diagrams fall back to listings)
mkadoc serve   # live-reload preview at http://127.0.0.1:8000
----

Or, with the devShell's `just` (see `justfile`): `just deps` once, then
`just check` / `just build` / `just serve` (extra args forward, e.g.
`just serve --port 9000`).

The `[plantuml]` diagram in the docs needs a running Kroki server
(`server_url: http://127.0.0.1:8080` in `mkadoc.yaml`) — e.g. the dotfiles
repo's `scripts/kroki.sh`, or any Kroki instance. Without one, `mkadoc check`
fails and diagram blocks fall back to their source listing.

== Nix

* `apps/mkadoc/flake.nix` builds the `mkadoc` package and the `mkadoc-test`
  check derivation (`nix flake check` inside `apps/mkadoc`).
* The repo root `flake.nix` re-exports that package and provides a devShell
  with `nodejs_24`, `nixfmt`, and `just` — loaded automatically by direnv
  (`.envrc`; run `direnv allow` once) or via `nix develop`.
* The `mkadoc` CLI is *not* installed from nix or direnv: it runs from source
  via npm. Either `npm link` once in `apps/mkadoc` (then plain `mkadoc`
  works), or invoke `node apps/mkadoc/bin/mkadoc.js` directly. Requires
  `npm install` in `apps/mkadoc` first.
* `nix flake check` at the repo root runs the mkadoc test suite and checks.
